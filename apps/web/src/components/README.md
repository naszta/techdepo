# Registry components

Copied from [dioxus-daisyui-components](https://github.com/sagikazarmark/dioxus-daisyui-components)
at commit `697c3da` with `dx components add <name> --path <checkout>`, and owned by this crate from
then on. `mod.rs` is generated by dx; app-level components live in `src/ui/`.

Installed: navbar, drawer, breadcrumbs, tabs, dropdown_menu, indicator, avatar, card, badge,
status, table, stat, steps, timeline, chat, progress, skeleton, loading, alert, toast, tooltip,
button, input, textarea, native_select, radio_group, switch, slider, toggle_group, field,
fieldset, label, dialog.

## Re-installing or adding one

`dx components add` panics inside this workspace (dx 0.7.10 resolves `default-members` relative
to the current directory, `workspace.rs:325`). Run it in a throwaway standalone crate instead and
copy the result:

```bash
cargo new --vcs none /tmp/scratch && cd /tmp/scratch && echo '[workspace]' >> Cargo.toml
dx components add <name> --path /path/to/dioxus-daisyui-components    # pinned checkout
cp -r src/components/<name> /path/to/techdepo/apps/web/src/components/
```

Components that depend on `field` (input, textarea, native_select, switch, slider) pull it from the
registry's git at an older revision; add them with `--force` and re-add `field` from the pinned path
last. The Cargo dependencies they need (`dioxus-primitives` git rev `bf007c1`, `dioxus-field 0.8`)
are already in `apps/web/Cargo.toml`; `DioxusLabs/components` is on cargo-deny's git allow-list.
